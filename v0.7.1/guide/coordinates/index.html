Coordinate systems and indexing

This guide is a work in progress. See the coordinate API reference and the indexing reference for the exact signatures.

Three coordinate kinds

LatticeCore distinguishes three ways of naming a lattice point:

  • RealSpace{D, T} — Cartesian coordinates, stored as an SVector{D, T}.
  • LatticeCoord{D} — an integer cell index plus a 1-based geometric sublattice id.
  • HigherDimCoord{DPhys, DHyper, T} — a point in the host lattice of a cut-and-project quasicrystal.

They talk to each other through to_real, to_lattice, and to_hyper, all of which dispatch on the concrete lattice so that the conversion uses the lattice's basis and (if applicable) projection.

Indexing is orthogonal to coordinates

Once you have a LatticeCoord, you still need a rule for turning it into a 1-based site index — that is the job of the AbstractIndexing hierarchy. LatticeCore ships RowMajor, ColMajor, and Snake with exhaustive round-trip tests.

Indexing is deliberately decoupled from coordinates: a lattice can switch its indexing without changing how it talks about positions.
