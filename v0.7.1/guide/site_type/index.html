Site types and layouts

This guide is a work in progress. See the concept column Site types and spin models for the physics.

Site type ≠ sublattice

LatticeCore separates two ideas that are traditionally conflated:

  • Geometric sublattice — where inside a unit cell the site sits (A, B, C, ...). Stored in LatticeCoord.sublattice.
  • Site type — what physical degree of freedom lives on the site (Ising spin, XY rotor, Heisenberg vector, ...). Described by AbstractSiteType and stored via an AbstractSiteLayout.

These axes are orthogonal: the same geometric sublattice can host any site type, and the same site type can sit on any sublattice.

Three layouts

LayoutWhen to use
UniformLayoutEvery site has the same type (most models)
SublatticeLayoutMixed-spin: A = Ising, B = XY, ...
ExplicitLayoutPer-site heterogeneity (quenched disorder)

UniformLayout has zero per-site memory overhead and lets the MC hot loop constant-fold the site type.

Built-in site types

IsingSite, PottsSite{Q}, XYSite, HeisenbergSite, EmptySite — see the site type reference for state_type / random_state / domain of each.

Element centering

The element_type trait lets a site type declare that its DOF lives on a BondCenter, PlaquetteCenter, or CellCenter rather than the default VertexCenter. This reserves headroom for dimer variables, gauge links, and flux fields without a breaking rewrite.
